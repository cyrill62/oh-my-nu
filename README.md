# Oh My Nu (omn)

A [Oh My Zsh](https://ohmyz.sh/)-style plugins for [nushell](https://www.nushell.sh/):
each plugin is a small nushell module of aliases and commands for a tool
(git, cargo, docker, rmux, portage...). Where it helps, commands return
nushell tables instead of text, so they can be filtered and sorted
(`gbt | where upstream == ""`, `dpst | where State == running`).

Built with AI tools: most of the code, tests and documentation were written
by an AI coding agent. See [How this project was made](#how-this-project-was-made).

Website: <https://cyrill62.github.io/oh-my-nu/>

## Install

Download `oh-my-nu-VERSION.tar.gz` (or `.zip`) from the
[releases](https://github.com/cyrill62/oh-my-nu/releases) and unpack it, or
clone the repository. The release archives hold only what runs: no
documentation, no website.

```nu
nu ~/Projects/perso/rmux-tools/oh-my-nu/install.nu            # the default set (see install.nu)
nu ~/Projects/perso/rmux-tools/oh-my-nu/install.nu git cargo  # or pick plugins
```

then open a new shell. Nothing is added to `config.nu`: the enabled plugins
are written as `use` lines to `~/.config/nushell/autoload/oh-my-nu.nu`,
which nushell loads at startup. A plugin whose tool is missing (its
`# requires:` line; `a|b` means either) is skipped with a notice; run
`omn sync` once the tool is installed. A plugin that doesn't parse (a broken
custom plugin, say) is left out too, so it can't break your shell; `omn list
--failed` shows the error.

## Managing plugins

```nu
omn list                 # plugins, enabled or not, and why one is skipped
omn list --enabled       # only the enabled ones (-e)
omn list --loaded        # only the ones new shells load (-l)
omn list --failed        # enabled but not loaded, and why: missing tool, error, not synced (-f)
omn enable docker eza    # then `omn reload` (restarts nu) or open a new shell
omn disable eza
omn aliases              # every alias/command of the enabled plugins
omn aliases git | where name =~ '^gp'
omn info rmux
omn sync                 # rewrite the autoload file
omn clashes              # names defined by several enabled plugins
omn paths
omn help                 # every command with its options and examples
omn help list            # one command in detail (also: omn --help)
omn --version            # the oh-my-nu version (-v)
```

## Plugins

157 plugins: 81 written individually (ports of Oh My Zsh's plugins plus new ones
for `apt`, `dpkg`, `rpm`, `pacman`, `yay`, `gentoo`, `openrc`, `cargo` and
`rmux`) and 76 generated by `tools/port-omz.py` from Oh My Zsh's alias plugins. Together they cover
every Oh My Zsh plugin that can exist in nushell: [COVERAGE.md](COVERAGE.md)
goes through all 373, including the ones that are completion-only, zsh line
editor or prompt features, or macOS-only.

Highlights:

- **git**: Oh My Zsh's names (`gst`, `gco`, `gcb`, `gp`, `gpf`, `gl`, `glog`,
  `grbi`, `gsta`...) plus `gcm`/`grbm` (main branch auto-detected), `gpsup`,
  `ggl`/`ggp`, `grt` (cd to repo root), `gwip`/`gunwip`, `gbda` (delete merged
  branches), and tables: `glt` (log), `gstt` (status), `gbt` (branches).
- **Package managers**: one prefix per tool (`apt*`, `dp*`, `rpm*`, `y*` for
  yum/dnf, `dnf*`, `z*` for zypper, `pac*`, `ya*` for yay, `em*`/`eq*` for
  portage). Commands that change the system run through `sudo` (or `doas`,
  or `$env.OMN_SUDO`; directly when already root); queries don't. Table
  helpers run the tool with `LC_ALL=C` so parsing works in any locale:
  `aptup`, `apth`, `dpls`, `dpsz`, `rpmls`, `rpmlast`, `ycu`, `zlut`,
  `pacexp`, `pacout`, `pacsz`, `yaaur`, `yaout`, `emlog`, `sct`.
- **rmux**: `ta`, `ts`, `tl`, `tksv`... (Oh My Zsh's tmux names) on rmux, or
  tmux when rmux isn't installed (`$env.OMN_MUX` to choose); `tat [name]`
  attaches or creates; `tst` / `twt` list sessions and windows as tables.
- **systemd**: `sc-<command>` for every systemctl command (root ones through
  sudo), `scu-<command>` for `--user`, `sc-enable-now`, `jf`/`jfu`, and `sct`.
- **git-flow-avh**: `gflfs NAME` / `gflff NAME`... for feature, bugfix,
  release, hotfix and support; the `…c` variants (`gflffc`, `gflrfc`,
  `gflhfc`...) finish or publish the branch you are on; `gcd`, `gcr`, `gch`
  switch to develop / the release / the hotfix in progress; `gflt` lists open
  flow branches as a table. Branch names and prefixes come from `git flow
  init`'s settings.
- **jump**: `mark [name]`, `jump name` (with completion), `marks`, `unmark`.
- **dotenv**: `dotenv [.env]` loads a file into the environment; `open
  .env | from dotenv` gives a record.
- **extract**: `extract [-r] ARCHIVE...` picks tar/unzip/7z/unrar/gunzip...
  from the extension; `-r` deletes the archive after success.

No plugin replaces a nushell built-in (that is why `ls`/`ll`/`l` use nushell's
`ls` and eza is under `lx*`; generated aliases call the external program, e.g.
`^ps`, when Oh My Zsh meant it). As in Oh My Zsh, two plugins may define the
same name (yarn's `yi` and yum's `yi`): `omn sync` warns when that happens
among enabled plugins, the plugin enabled last wins, and `omn clashes` lists
them. The default set has no clashes; the tests check both rules.

Plugins with startup code: `ssh-agent` (starts or reuses an agent, then adds
your keys unless `$env.OMN_SSH_AGENT_LAZY = true`), `gpg-agent`,
`colored-man-pages`, `hitchhiker` (prints a quote, like Oh My Zsh), and
`uv-env` / `poetry-env`, which add a `cd` hook that activates a project's
virtualenv.

## Custom plugins

Put `NAME.nu` in `~/.config/oh-my-nu/custom/` and `omn enable NAME`. A
custom plugin with the name of a built-in one replaces it.

```nu
# description: my shortcuts
# requires: kubectl

export alias k = kubectl
export alias kgp = kubectl get pods

# Pods as a table
export def kpods [] { ^kubectl get pods -o json | from json | get items.metadata.name }
```

Plugins can `use ../lib/root.nu [as-root c-locale]` for the shared root and
C-locale helpers, and `export-env { ... }` to set variables at startup (see
`colored-man-pages.nu`).

Aliases must be a single command (`export alias gst = git status`); use
`export def --wrapped name [...rest] { ^tool sub ...$rest }` for anything
else. A module can't export a command with its own name: call it `main`
(as `extract.nu` does).

## Regenerating from Oh My Zsh

```sh
tools/port-omz.py ~/.oh-my-zsh/plugins yarn rails ...   # rewrite generated plugins
tools/coverage.py > COVERAGE.md
```

Plugins written individually (without the `# generated by tools/port-omz.py`
line) are never overwritten.

## Releasing

The version lives in `VERSION`; `tools/set-version.nu` copies it into
`oh-my-nu.nu`, where `omn --version` reads it:

```sh
tools/set-version.nu            # after editing VERSION by hand
tools/set-version.nu 0.2.0      # write VERSION and oh-my-nu.nu
tools/set-version.nu minor      # or bump major, minor or patch
tools/set-version.nu --check    # fail if the two disagree (the tests run this)
```

Pushing a `vX.Y.Z` tag publishes a GitHub release
(`.github/workflows/release.yml`):

```sh
tools/set-version.nu 0.2.0
git commit -am "Release 0.2.0"
git tag v0.2.0
git push --follow-tags
```

The workflow checks that the tag, `VERSION` and `oh-my-nu.nu` agree, then
attaches `oh-my-nu-0.2.0.tar.gz`, `.zip` and `SHA256SUMS`. The archives leave
out the root `*.md` files, `www/` and `.github/`. A version with a suffix
(`1.0.0-rc.1`) becomes a pre-release.

## Website

`www/` is the project's website (Vike, React, Motion and i18next, in English
and French). It reads the plugin headers, `VERSION`, `COVERAGE.md` and the
test list at build time, so it follows the repository without edits.
`.github/workflows/pages.yml` builds it and publishes it to GitHub Pages on
every push to `main` that touches those files (enable it once in Settings >
Pages > Source: GitHub Actions).

```sh
cd www
npm install
npm run dev                          # http://localhost:3000
BASE_URL=/oh-my-nu/ npm run build    # what the workflow runs; output in dist/client
```

The logo is `www/public/logo.svg`.

## Tests

```nu
nu tests/run.nu
```

Checks that every plugin parses without warnings, that no name shadows a
nushell command or is defined twice, the manager (enable/disable/sync/
custom/missing tools) in a sandbox, `extract` on real archives, the git
helpers in a scratch repository, the rmux helpers on a throwaway server, the
package-manager plugins against fake `apt`/`dpkg-query`/`rpm`/`dnf`/
`pacman`/`yay`/`systemctl`/`sudo` binaries (exact command lines, root only
where expected, table parsing), the utility plugins, git-flow against the real
tool, and the Oh My Zsh ports (URLs opened, generated wrappers, gradle, lando,
pj, aws, git-commit, ua, tt, shell-proxy, uv-env's hook, ssh, and ssh-agent
starting and reusing its own agent). Every nushell they start gets a scratch
`HOME`, so nothing touches your real config, keys or agent.

## How this project was made

oh-my-nu was made with AI tools, not written alone by its author. The
plugins, the `omn` manager, the generators in `tools/`, the tests and this
documentation were mostly written by an AI coding agent,
[Claude Code](https://claude.com/claude-code) running Anthropic's Claude
models, working from the author's requests: which tools to cover, how
commands should behave, and what to fix. The author directed the project
and tested it on their own machine.

Most of the work comes from Oh My Zsh's plugins: 76 plugins were converted
from them by a script, and many others are ports of them.

What that means for you:

- The test suite (`nu tests/run.nu`) covers a lot, but not everything: the
  network plugins (transfer, sprunge, qrcode, quotes, gitignore), `otp` and
  `catimg` aren't tested. Some commands may be wrong for setups the tests
  don't fake.
- Read a plugin before you enable it, especially ones that run commands as
  root (`as-root` in `lib/root.nu`) or start programs (`ssh-agent`).
- Bug reports and fixes are welcome, whoever or whatever wrote them.
  [AGENTS.md](AGENTS.md) holds the conventions for AI agents (and people)
  changing the code.
