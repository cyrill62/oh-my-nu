# AGENTS.md

Notes for AI coding agents (and people) working on oh-my-nu. Read
[README.md](README.md) first for what the project does.

## Layout

| Path | What it is |
| --- | --- |
| `oh-my-nu.nu` | the `omn` manager module (enable, disable, sync, list, help...) |
| `install.nu` | `nu install.nu [PLUGIN...]`: enables a default set |
| `lib/root.nu` | shared helpers: `as-root`, `c-locale`, `open-url`, `random-fortune`, `omz-plugin-dir`, `clipcopy` |
| `plugins/*.nu` | one nushell module per plugin |
| `tools/port-omz.py` | generates plugins from Oh My Zsh's alias plugins |
| `tools/coverage.py` | writes `COVERAGE.md` (every Oh My Zsh plugin and how it's covered) |
| `tools/set-version.nu` | copies `VERSION` into `oh-my-nu.nu` |
| `tests/run.nu` | the test suite |
| `www/` | the website (Vike + React + Motion + i18next), built from the files above |
| `.github/workflows/pages.yml` | builds `www/` and deploys it to GitHub Pages |
| `.github/workflows/release.yml` | on a `vX.Y.Z` tag, publishes a release archive without the root `*.md` files, `www/` and `.github/` |

Target nushell version: 0.116. Plugins are pure nushell; no compiled nushell
plugins.

## Plugins

- Start each file with `# description:` and `# requires:` lines. `requires`
  lists the tools that must be on `PATH`; `a|b` means either one is enough.
  The manager skips a plugin when a tool is missing.
- Use `export alias` only for a single command. Anything else is
  `export def --wrapped name [...rest] { ^tool sub ...$rest }`.
- Never shadow a nushell built-in command. Prefix external commands that
  share a name with a built-in with `^`.
- A module can't export a command with its own name: call it `main`.
- Names may clash between plugins, as in Oh My Zsh (the last enabled one
  wins), but not within `install.nu`'s default set.
- Return tables rather than text where the output is a list of things.
- Use `as-root` from `lib/root.nu` for commands that need root, and
  `c-locale` when parsing a tool's output (the author's machine is French).
- Startup code (`export-env`) must not fail or slow the shell: warn and
  carry on.

### Generated plugins

Files with a `# generated by tools/port-omz.py` line are generated. Change
`tools/port-omz.py` (its `REQUIRES` overrides, skip rules...) and rerun it
instead of editing them; the script never overwrites the other plugins. After
adding, removing or regenerating plugins, rerun `tools/coverage.py >
COVERAGE.md` and update the plugin counts and tables in README.md.

## Manager

- `omn` writes `use "<file>" *` lines to `$nu.user-autoload-dirs.0/oh-my-nu.nu`
  and keeps the enabled list in `~/.config/oh-my-nu/plugins.nuon`. Tests
  override both with `OMN_AUTOLOAD_FILE` and `OMN_CONFIG_DIR`.
- Every command has a doc comment, parameter descriptions and `@example`
  attributes: `omn help` is built from them.
- The version is the `VERSION` file. Change it with
  `tools/set-version.nu X.Y.Z` (or `major`/`minor`/`patch`), never by editing
  the constant in `oh-my-nu.nu`.

## Tests

```sh
nu tests/run.nu                      # all groups; must all print "ok"
OMN_TEST_DIR=/some/scratch nu tests/run.nu
```

`OMN_TEST_DIR` is reused between runs: delete it first, or tests fail with
"Destination file already exists". Add a test for every new command or
behaviour. Tests fake external tools with scripts in scratch `bin`
directories and check the exact command lines.

## Website

- `www/pages/+data.ts` reads `plugins/*.nu`, `VERSION`, `COVERAGE.md` and
  `tests/run.nu` at build time. Keep the plugin header format stable, or
  update that file with it.
- Every visible string goes through i18next: add it to both `www/i18n/en.ts`
  and `www/i18n/fr.ts` (the French type is checked against the English one).
- Links and assets must go through `import.meta.env.BASE_URL` (in config
  files, `process.env.BASE_URL`): the site lives under `/oh-my-nu/`.
- Animations go through Motion, and `<MotionConfig reducedMotion="user">` in
  `+Layout.tsx` handles reduced motion. Always pass `initial` and `animate`;
  don't drop them conditionally, or the server-rendered `opacity: 0` stays.
- Check with `npm run typecheck` and `BASE_URL=/oh-my-nu/ npm run build`.

## Safety rules

These come from real mistakes; keep to them.

- Never touch the user's real setup: no edits to `~/.config/nushell`,
  `~/.config/oh-my-nu`, `~/.ssh`, shell rc files, and no running `omn
  enable/sync` or `install.nu` outside a sandbox. Every nushell the tests
  start gets a scratch `HOME` (`nu-run` in `tests/run.nu`); keep it that way.
- Clear inherited state before testing a plugin that talks to a running
  service. A test once killed the user's own ssh-agent through an inherited
  `SSH_AGENT_PID`. Only kill processes the test itself started, and check
  that the pid is really one of them.
- Network plugins (transfer, sprunge, qrcode...) aren't tested: don't call
  real services from tests.
- Don't commit, push or publish unless asked.
